# Яндекс Музыка для Volumio · Media Str

Минимальная веб-оболочка для Raspberry Pi с Volumio, сенсорным экраном и USB-ЦАПом. Проект развивается в клиент Яндекс Музыки с привычной навигацией, лайками и редактированием плейлистов в аккаунте Яндекса.

Репозиторий: **[GorINIch73/volumio_Ya](https://github.com/GorINIch73/volumio_Ya)**.

## Что работает в версии 0.1.0

- Адаптивная тёмная оболочка: главная, обслуживание и логи.
- Установка отдельного сервиса на Volumio с автоматическим запуском через systemd.
- Вход в интерфейс с отдельным паролем администратора.
- Проверка и установка обновления напрямую из GitHub-репозитория, без ручной загрузки ZIP.
- Загрузка ZIP через браузер как запасной способ; проверка содержимого и контрольных сумм.
- Проверка запуска новой версии, автоматический откат при неудаче и ручной возврат предыдущей версии.
- Независимая резервная страница обслуживания, доступная при сбое основного интерфейса.
- Просмотр, фильтрация и скачивание логов приложения и обновлений.

**Музыкальный плеер и авторизация Яндекса в новой оболочке ещё не подключены.** Кнопки воспроизведения отключены, демонстрационных треков нет. Логи действующего музыкального плагина Volumio пока не собираются. Уже установленный плагин Яндекс Музыки продолжает работать отдельно.

Это первый этап [плана разработки](PLAN.md). Проверки на компьютере не заменяют проверку на конкретной Raspberry и версии Volumio.

## Архитектура

```text
Смартфон / сенсорный экран
            │
            ▼
Сервис обслуживания :8099       ← остаётся доступным при сбое приложения
            │
            ├── обновление / откат / логи
            │
            └── процесс веб-приложения
                        │
                        └── интеграция с Volumio и Яндексом — следующий этап
```

Сервис работает от отдельного пользователя `mediastr`, без root и без доступа к настройкам музыкального плагина. Веб-пакеты обновляют приложение (`app.py` и `web/`); код самого сервиса обслуживания обновляется повторным запуском установщика.

## Установка на Volumio

### Требования

- Работающая Volumio на Raspberry Pi; целевое устройство — Pi 5.
- Python **3.9 или новее**, Git, systemd и `runuser` (util-linux).
- SSH-доступ для первоначальной установки.
- Свободный TCP-порт **8099**, не менее 96 МБ свободного места для подготовки обновления.
- Телефон/компьютер и Raspberry в одной локальной сети.

Рабочий сервис использует только стандартную библиотеку Python, без npm и pip. Установщик проверяет требования, но не обновляет системный Python и не устанавливает пакеты ОС автоматически. Если проверка не прошла, сначала уточните версию Volumio и её возможности обновления.

### 1. Включить SSH

Откройте `http://volumio.local/dev` или `http://IP-АДРЕС-VOLUMIO/dev`, найдите **SSH → Enable**. См. [официальную инструкцию Volumio](https://help.volumio.com/en/articles/13-how-do-i-enable-ssh-connection).

На компьютере подключитесь к устройству:

```bash
ssh volumio@volumio.local
```

Если имя не определяется, используйте IP, например `ssh volumio@192.168.1.50`. Введите SSH-пароль устройства.

### 2. Скачать репозиторий и установить

Выполните **на Raspberry, в SSH-сессии**:

```bash
git clone https://github.com/GorINIch73/volumio_Ya.git
cd volumio_Ya
sudo bash scripts/install.sh
```

Если репозиторий уже скачан, перейдите в существующий каталог. Перед `git pull --ff-only` проверьте, что в нём нет несохранённых собственных изменений.

Установщик собирает приложение, создаёт пользователя `mediastr`, устанавливает сервис `media-str.service`, проверяет запуск приложения и включает автозапуск. В конце он выводит адрес, логин **admin** и сгенерированный пароль.

Это **отдельный сервис**, а не ZIP для штатного менеджера плагинов Volumio. В списке «Установленные плагины» он пока не появляется. Команда `volumio plugin install` для этого репозитория не используется.

### 3. Открыть интерфейс

На компьютере, телефоне или в браузере сенсорного экрана откройте:

```text
http://volumio.local:8099
```

Либо `http://IP-АДРЕС-VOLUMIO:8099`. Войдите как **admin** с паролем из установщика.

Повторно прочитать первоначальный пароль на Raspberry:

```bash
sudo cat /var/lib/media-str/initial-password.txt
```

Этот пароль защищает обслуживание устройства и не связан с аккаунтом Яндекса. Версия 0.1 использует HTTP и предназначена для доверенной локальной сети; не открывайте порт 8099 в интернет. HTTPS и управление пользователями пока не реализованы.

### 4. Настроить экран и ЦАП

- Для сенсорного экрана используйте совместимый с вашей Volumio плагин дисплея/браузер в режиме киоска, открывающий адрес `http://127.0.0.1:8099`.
- При первом открытии понадобится вход `admin`. Настройка сохранения входа зависит от браузера киоска; автоматический вход пока не реализован.
- USB-ЦАП выбирается в настройках воспроизведения **Volumio → Output Device**. Проверьте звук в уже работающем источнике Volumio.
- Новая оболочка 0.1 сама музыку не воспроизводит и не меняет аудиовыход.

## Обновление через браузер

### Установить прямо из GitHub

1. Откройте **Обслуживание → Обновление из репозитория**.
2. Нажмите **Проверить обновления**.
3. Интерфейс покажет короткий идентификатор сборки и описание изменения.
4. Нажмите **Установить из GitHub** и подтвердите выбранную сборку.
5. Дождитесь сообщения **«Версия запущена и проверена»**, затем обновите страницу браузера.

Raspberry сама скачивает код из публичного репозитория **[GorINIch73/volumio_Ya](https://github.com/GorINIch73/volumio_Ya)**. Отдельный GitHub Release, собранный ZIP на компьютере и SSH для обычного обновления приложения не нужны.

Используется основная ветка, выбранная в настройках GitHub; имя `main` или `master` не зашито. При проверке фиксируется конкретный commit. Установка скачивает именно его, даже если в ветке уже появились следующие изменения. Идентификатор установленного commit сохраняется, поэтому новая сборка определяется и без изменения номера версии приложения. Для пакета, установленного локально без этой информации, первая проверка предложит установить сборку репозитория.

Обновление доступно после публикации кода в основной ветке. Нужны файлы `app/manifest.json`, `app/app.py` и `app/web/`. Если в репозитории пока только README и план, установка покажет понятную ошибку и сохранит работающую версию. Репозитории с закрытым доступом в этом выпуске не поддерживаются.

Проверка GitHub выполняется только по нажатию кнопки; регулярное обновление статуса в интерфейсе не расходует лимит GitHub API. Ошибка сети или лимит запросов не останавливают работающее приложение.

### Запасной вариант: установить ZIP вручную

На компьютере с копией репозитория:

```bash
python3 scripts/build.py
```

Появится `dist/media-str-0.1.0.zip`. Версия берётся из `app/manifest.json`. В разделе обслуживания раскройте **Загрузить ZIP вручную**, выберите файл до 16 МБ и нажмите **Установить файл**.

### Проверка и откат

Для обоих способов сервис проверяет формат, версию протокола, требуемый Python, пути файлов и контрольные суммы. Новая версия подготавливается отдельно; активная версия меняется после успешного запуска. При ошибке запуска восстанавливается прежнее приложение. Проверка касается запуска HTTP-приложения, а не работоспособности всех его функций.

Кнопка **Вернуть предыдущую версию** выполняет ручной откат. Хранятся текущая и предыдущая успешная версии. Пароль обслуживания и его настройки не включаются в пакет.

Из репозитория переносится только `app/`; установочные и сборочные скрипты репозитория автоматически не исполняются. Источник фиксирован, скачивание идёт по HTTPS. Обновление доверяет владельцу репозитория; криптографическая проверка подписей коммитов пока не реализована. Для ручного ZIP контрольные суммы обнаруживают повреждения, но не подтверждают автора — используйте доверенные сборки.

### Если интерфейс сломался

Откройте независимую страницу:

```text
http://volumio.local:8099/maintenance
```

Она позволяет проверить и установить сборку из GitHub (Check GitHub / Install from GitHub), загрузить исправленный ZIP, выполнить откат и скачать логи. Если сам сервис обслуживания не запускается, потребуется SSH.

### Обновить сам сервис обслуживания

Если уже установлен первый вариант 0.1 без кнопок GitHub, один раз выполните команды ниже: новая возможность находится в сервисе обслуживания и обычный ZIP приложения её не добавит.

В SSH-сессии, из каталога репозитория:

```bash
git pull --ff-only
sudo bash scripts/install.sh
```

Сервис обслуживания будет кратко остановлен. Повторный запуск сохраняет его пароль и устанавливает приложение из текущего checkout. Прежний файл сервиса сохраняется как `/opt/media-str/maintenance.py.previous`.

## Настройка аккаунта Яндекс Музыки и получение токена

**Этот раздел пока относится к существующему музыкальному плагину `yandex_music`, установленному в Volumio.** В оболочке Media Str 0.1 нет поля аккаунта Яндекса; вводить токен вместо пароля `admin` не нужно.

В [исходном плагине achechulin](https://github.com/achechulin/volumio-plugins-sources/tree/master/yandex_music) откройте **Плагины → Установленные → Yandex Music → Настройки**, выберите способ входа **Токен**, вставьте токен и нажмите **Войти**. Для полноценного воспроизведения нужна соответствующая подписка Яндекса.

### Получить токен через подтверждение в браузере

В актуальной документации неофициального клиента `yandex-music` описан **OAuth Device Flow**: локальная программа показывает ссылку и код, вы подтверждаете вход на странице Яндекса, программа получает токен. Пароль аккаунта вводится на стороне Яндекса. [Описание способа у автора библиотеки](https://github.com/MarshalX/yandex-music-api#доступ-к-вашим-данным-яндексмузыка).

На своём компьютере с Python, из каталога этого репозитория, создайте отдельное окружение:

```bash
python3 -m venv .venv-token
.venv-token/bin/python -m pip install --upgrade yandex-music
.venv-token/bin/python scripts/get_yandex_token.py
```

На Windows команды для запуска окружения:

```powershell
py -m venv .venv-token
.venv-token\Scripts\python.exe -m pip install --upgrade yandex-music
.venv-token\Scripts\python.exe scripts/get_yandex_token.py
```

Далее:

1. Откройте ссылку, которую напечатала программа.
2. Войдите в нужный аккаунт Яндекса, введите показанный код и подтвердите запрос.
3. Дождитесь завершения программы. Она сохранит `access_token` в `~/.config/media-str/yandex-access-token.txt` и выведет полный путь.
4. Откройте этот файл локально и скопируйте его содержимое в поле **Токен** музыкального плагина.
5. Проверьте вход и открытие своих плейлистов.

Скрипт не выводит сам токен в терминал, не отправляет его в Media Str и не меняет коллекцию. В Unix файл создаётся с правами `0600`; на Windows доступ определяется правами профиля пользователя. Существующий файл не перезаписывается. Для повторного получения сначала сохраните его под другим именем.

Токен имеет срок действия. Скрипт показывает `expires_in`, но не реализует обновление через `refresh_token`; при истечении получите новый токен. Совместимость такого токена с конкретной установленной сборкой плагина нужно проверить.

Если установленная версия библиотеки ещё не содержит `device_auth` или Яндекс отклоняет этот способ для аккаунта, используйте альтернативы из [документации автора библиотеки](https://ym.marshal.dev/). Не пытайтесь подставлять cookies сайта вместо OAuth-токена. Не прикладывайте файл токена к issues, логам или скриншотам.

## Логи и диагностика

В разделе **Логи** доступны последние 128 КБ журнала приложения и обновлений:

- фильтр уровня: все / ошибки / предупреждения / информация;
- пауза обновления;
- копирование (в браузерах, запрещающих буфер обмена по HTTP, текст выделяется для ручного копирования);
- скачивание файла.

Журнал ограничен по размеру и ротируется. Маскируются известные поля с токенами/паролями и параметры HTTP-ссылок. Это не гарантия удаления любого возможного секрета из произвольного сообщения: просмотрите отчёт перед отправкой.

Логи systemd для сервиса обслуживания:

```bash
sudo journalctl -u media-str -n 100 --no-pager
```

Живой просмотр:

```bash
sudo journalctl -u media-str -f
```

Логи самого Volumio (пока только через SSH):

```bash
sudo journalctl -u volumio -n 200 --no-pager
```

Завершить просмотр — `Ctrl+C`. К сообщению об ошибке приложите версию приложения и Volumio, последовательность действий и очищенный фрагмент логов.

| Проблема | Что проверить |
| --- | --- |
| Не открывается `volumio.local:8099` | Попробовать IP; проверить `sudo systemctl status media-str` |
| Установщик сообщает о Python | Нужен Python ≥ 3.9; не заменять системный Python без проверки совместимости Volumio |
| Новая версия не запустилась | Логи обновления; предыдущая версия должна восстановиться |
| Основная страница не работает | Открыть `/maintenance` |
| Кнопки музыки отключены | Это ожидаемо в 0.1: интеграция с плеером — следующий этап |
| Лайки не появляются в Яндексе | Обратная синхронизация ещё не реализована |

## Локальный запуск и тесты

На Linux с Python ≥ 3.9:

```bash
bash scripts/dev.sh
```

Откройте `http://127.0.0.1:8099`. Логин — `admin`; пароль находится в `.dev/initial-password.txt`. Разработка использует отдельные данные `.dev/`, системный сервис не устанавливается. Остановить — `Ctrl+C`.

Для проверки правки соберите новый ZIP и загрузите через интерфейс; автоматическая перезагрузка исходников пока не реализована. Повторный запуск `scripts/dev.sh` тоже собирает и устанавливает текущие исходники.

Тесты:

```bash
python3 -m unittest discover -s tests -v
```

Они запускают локальные HTTP-процессы и проверяют установку, обновление из GitHub на фиктивных ответах, фиксацию commit, ошибки сети, откат, восстановление, авторизацию, защиту запросов и отклонение опасных/повреждённых архивов. Доступ к аккаунту Яндекса не нужен. Реальное отключение питания, systemd на Volumio и аудиотракт требуют отдельной проверки на Raspberry.

Структура проекта:

```text
app/                  Обновляемое приложение и веб-интерфейс
service/              Независимый сервис обслуживания
scripts/install.sh    Первоначальная установка на Volumio
scripts/build.py      Сборка ZIP-обновления
scripts/dev.sh        Локальный запуск
scripts/get_yandex_token.py  Получение токена на компьютере пользователя
tests/                Интеграционные проверки
PLAN.md               План следующих этапов
```

## Дальнейшая разработка

Следующий этап — соединить оболочку с установленным плагином и очередью Volumio, затем добавить лайки, редактирование плейлистов, поиск и «Мою волну». Сервис обслуживания уже выделен отдельно, чтобы эти изменения можно было испытывать через браузер.

Интеграция Яндекса неофициальная. Проект независим от Яндекса и Volumio. Музыкальная часть планируется на основе [achechulin/yandex_music](https://github.com/achechulin/volumio-plugins-sources/tree/master/yandex_music), в `package.json` которого указана лицензия ISC. Его код в текущий выпуск ещё не перенесён. Лицензия собственных доработок пока не выбрана.
