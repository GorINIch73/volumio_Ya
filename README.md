# YaM — Яндекс Музыка для Volumio

Версия **0.4.9** — штатный плагин категории `music_service` для Volumio 4 (Bookworm). Управление находится в **Плагины → Установленные**, библиотека — в **Обзор → YaM**, воспроизведение — в общем плеере Volumio. Этот же интерфейс доступен на сенсорном экране и телефоне.

Репозиторий: [GorINIch73/volumio_Ya](https://github.com/GorINIch73/volumio_Ya).

Реализованы вход по токену, проверка аккаунта и выход, собственные плейлисты и «Мне нравится», рекомендации, новые релизы, популярные плейлисты и альбомы с обложками, страницы по 50 треков, добавление отдельного трека в очередь и воспроизведение через MPD. В очереди сохраняется ID трека; свежая MP3-ссылка запрашивается перед каждым запуском. Пауза, продолжение, перемотка и переключение выполняются средствами Volumio.

**Сборка пока предназначена для разработки и проверки на устройстве.** На целевой Volumio уже проверены установка, вход и загрузка плейлиста; воспроизведение подтверждено пользователем после исправления очереди запросов в 0.4.4. В 0.4.7 добавлена передача обложек треков в список, очередь и плеер; отображение на устройстве ещё нужно проверить. Локальные тесты проверяют контракт плагина и обмен с Python; установку, сенсорный интерфейс, реальный аккаунт, переходы между треками и звук через ЦАП необходимо проверить на целевой Raspberry. Плагин ещё не опубликован в магазине Volumio. Поиск, «Моя волна», изменение лайков/плейлистов и добавление целого плейлиста пока не реализованы.

## Сборка

На компьютере разработчика нужны Node.js с npm и Python 3.9+:

```bash
npm ci --ignore-scripts --no-audit --no-fund
python3 scripts/build.py
```

Результат: `dist/yam-0.4.9.zip`. Это ZIP плагина Volumio: `package.json`, `index.js`, `config.json`, `UIConfig.json`, установочные скрипты, Kew и внутренний Python-компонент расположены без внешней папки. Данные аккаунта в пакет не входят.

## Первая установка на Volumio

Требования: Volumio 4 / Bookworm, Node.js 14+, Python 3.9+, доступ к интернету для Яндекса. Архитектурно зависимых библиотек нет. Для воспроизведения требуется подходящая подписка Яндекса. Установщик проверяет среду, не обновляет ОС и не меняет настройки аудиовыхода.

1. **На компьютере**, из каталога репозитория, скопируйте ZIP на устройство:

   ```bash
   scp dist/yam-0.4.9.zip volumio@volumio.local:/home/volumio/
   ```

   Если имя `volumio.local` не разрешается, замените его IP-адресом устройства, например `192.168.1.117`.

2. Подключитесь с компьютера по SSH:

   ```bash
   ssh volumio@volumio.local
   ```

3. **На Volumio**, от пользователя `volumio` (без `sudo`), распакуйте пакет в новый пустой каталог:

   ```bash
   yam_install_dir=$(mktemp -d /home/volumio/yam-install.XXXXXX)
   cd "$yam_install_dir"
   python3 -m zipfile -e ~/yam-0.4.9.zip .
   chmod +x install.sh uninstall.sh
   volumio plugin install
   ```

4. Дождитесь сообщения об успешной установке. Если после успеха CLI не завершается, нажмите `Ctrl+C`. Затем перезапустите Volumio:

   ```bash
   volumio vrestart
   ```

5. После восстановления интерфейса откройте **Плагины → Установленные → YaM**, включите плагин и откройте настройки.
6. Вставьте OAuth-токен без префикса `OAuth`, нажмите **Войти по токену**, затем **Проверить аккаунт**.
7. В **Обзоре** откройте источник **YaM**, выберите «Мне нравится» или свой плейлист. Меню трека позволяет добавить его в общую очередь Volumio.

Это процедура разработки через [штатную CLI Volumio](https://developers.volumio.com/plugins/writing-a-plugin). Для публичного распространения после проверки потребуется публикация в магазине. Просто копировать папку в `/data/plugins` или редактировать `plugins.json` не нужно.

## Получение токена

На компьютере с Python создайте отдельное окружение и запустите помощник:

```bash
python3 -m venv .venv-token
.venv-token/bin/python -m pip install --upgrade yandex-music
.venv-token/bin/python scripts/get_yandex_token.py
```

Откройте напечатанную ссылку, введите код и подтвердите вход на стороне Яндекса. Скрипт сохранит токен в `~/.config/yam/yandex-access-token.txt`; скопируйте его в настройки плагина. Сам токен в терминал не выводится, существующий файл не перезаписывается. На Unix файл создаётся с правами `0600`. Если установленная библиотека не поддерживает `device_auth`, скрипт сообщит об этом. При истечении токена получите новый: автоматического продления пока нет.

## Обновление и удаление

### Обновление установленного плагина вручную

Скопируйте `dist/yam-0.4.9.zip` на устройство. Для уже установленного **YaM** с идентификатором `yam` используйте **update**, а не install. В новой пустой папке на Volumio:

```bash
yam_update_dir=$(mktemp -d /home/volumio/yam-update.XXXXXX)
cd "$yam_update_dir"
python3 -m zipfile -e ~/yam-0.4.9.zip .
chmod +x install.sh uninstall.sh
volumio plugin update
```

Дождитесь 100% и сообщения об успешном обновлении. В некоторых русифицированных сборках CLI после успеха не закрывается; тогда завершите только эту команду через `Ctrl+C`. Затем выполните `volumio vrestart`, чтобы загрузить новый Node.js-код. Удалять плагин перед обновлением не нужно: удаление может стереть аккаунт.

### Обновление из репозитория по кнопке

В настройках появился раздел **Обновление из GitHub**:

1. **Проверить обновление** — получает последний commit основной ветки `GorINIch73/volumio_Ya`, загружает именно эту ревизию и проверяет пакет. Музыка на этом шаге не останавливается.
2. Поле состояния показывает версию и короткий commit подготовленной сборки.
3. **Установить обновление** — передаёт подготовленный пакет штатному менеджеру Volumio. Музыка останавливается; после успешной установки Volumio автоматически перезапускается. Подождите восстановления интерфейса.

Фоновых проверок и установки по таймеру нет. Код должен быть **опубликован в GitHub**: кнопка не видит локальные изменения на компьютере. Старые версии из репозитория отвергаются. Если изменился набор npm-зависимостей, потребуется новый готовый ZIP; текущий обновлятор включает установленную Kew без скачивания дополнительных зависимостей. Подготовленный пакет действует до остановки плагина; после перезапуска нажмите проверку снова.

Сохранённый аккаунт и журнал лежат отдельно от кода. Перед установкой создаётся `previous-plugin.zip` в `/data/configuration/music_service/yam/`; это предыдущий код без токенов. При сбое самого менеджера Volumio автоматический откат не гарантируется. Для восстановления скопируйте этот ZIP в новую пустую папку, распакуйте и выполните `volumio plugin update`, затем `volumio vrestart`. Если перезапуск после успешного обновления не выполнился автоматически, используйте перезагрузку из меню Volumio.

Отключение останавливает Python-компонент и убирает источник из «Обзора». Удаление выполняется из менеджера плагинов Volumio; сохранность настроек при удалении не гарантируется. Плагин не устанавливает системные службы, правила sudo или отдельный веб-сервер.

## Архитектура и данные

Отображаемое название плагина — **YaM**. Техническое имя пакета и идентификатор источника — `yam`; URI треков имеют вид `yam/track/123`.

```text
Volumio → index.js (music_service/yam)
             ├── Browse / настройки / очередь
             ├── MPD → выбранный аудиовыход Volumio
             └── Python bridge (stdin/stdout) → API Яндекс Музыки
```

Python запускается при включении плагина от пользователя Volumio и завершается при отключении. При завершении процесса Volumio закрывается канал stdin, и компонент тоже выходит. Сетевой порт для взаимодействия с Python не нужен. Обновления скачиваются по HTTPS, затем передаются локальному менеджеру Volumio. Сбой компонента отклоняет ожидающие запросы и убирает источник; повторное включение запускает его заново.

Аккаунт хранится в каталоге настроек плагина `/data/configuration/music_service/yam/`, отдельно от обновляемого кода. Поле токена в настройках всегда пустое: сохранённое значение не возвращается в интерфейс. Логи плагина не содержат токенов или MP3-ссылок; внутренние журналы самого MPD/Volumio могут содержать адрес воспроизводимого файла.

Kew включён в пакет для совместимости с promises Volumio. `app/app.py` — библиотека клиента Яндекса: аккаунт, плейлисты и получение MP3-ссылок. `python/bridge.py` вызывает её через stdin/stdout; управление воспроизведением выполняет `index.js` через Volumio.

## Проверка и диагностика

```bash
npm test
python3 -m unittest discover -s tests -v
python3 scripts/build.py
```

Node-тесты требуют Node.js 18+. Сам плагин рассчитан на Node.js 14+. Проверки используют фиктивные ответы Яндекса и Volumio, не выполняют операции с настоящей коллекцией.

В настройках откройте **Журнал и ошибки**. Кнопка **Обновить** обновляет поле **Последняя ошибка**; его можно выделить и скопировать как обычный текст. **Открыть журнал** показывает последние 100 записей с временем, версией, операцией и этапом ошибки. Ошибка сохраняется после исчезновения уведомления и перезапуска. После сбоя воспроизведения скопируйте поле последней ошибки или соответствующие строки журнала.

Журнал фиксирует ошибки библиотеки, получения MP3-ссылки, команд MPD, запуска Python и обновления. В том числе сохраняются ошибки MPD, которые Volumio возвращает в успешном ответе и показывает только коротким уведомлением. Токены, заголовки авторизации и URL скрываются до записи; HTML в просмотрщике экранируется. Журнал ограничен двумя файлами примерно по 256 КиБ; последняя ошибка хранится отдельно. Файлы находятся в каталоге настроек плагина.

Дополнительный системный журнал на устройстве доступен через `sudo journalctl -u volumio -n 100 --no-pager`. Если источник исчез после ошибки, выключите и включите плагин; проверьте Python, подключение к интернету и аккаунт в настройках.

Проверка на устройстве перед следующим этапом:

- Установка ZIP, включение/отключение без дублирования источника и оставшихся процессов.
- Вход, перезапуск Volumio и сохранение аккаунта; выход без раскрытия токена в UI.
- «Мне нравится», свои плейлисты, следующая/предыдущая страница, недоступные треки.
- Добавление двух треков в очередь, запуск, пауза, перемотка, следующий трек и автоматический переход.
- Смена источника, отключение во время запроса, обновление ZIP и удаление.
- Работа сенсорного экрана и телефона с одним плеером; звук через выбранный ЦАП.

Контракт сверялся с официальными описаниями [структуры плагина](https://developers.volumio.com/plugins/plugin-structure), [жизненного цикла](https://developers.volumio.com/plugins/index-js) и [музыкального источника](https://developers.volumio.com/plugins/music-service). Следующие этапы — в [PLAN.md](PLAN.md).

### Автоматический экран трека (0.4.7)

После запуска трека YaM из списка интерфейс открывает экран воспроизведения с обложкой.
Переход происходит только в браузере, где нажали трек, после успешной команды запуска MPD.
Добавление в очередь, другие источники и автоматическая смена трека экран не переключают.
После обновления перезагрузите страницу браузера; на сенсорном экране также требуется обновление страницы.

Для этого install.sh добавляет небольшой скрипт в `/volumio/http/www/index.html` (и обновляет его gzip-копию, если она есть).
Основной JavaScript Volumio не изменяется. Расширение рассчитано на Angular-интерфейс Volumio, проверенный по коду устройства 4.119.
Удаление плагина удаляет вставку; уже открытые страницы нужно перезагрузить.
Обновление самой ОС Volumio может удалить вставку — тогда повторно установите обновление YaM.
Проверки локальные; переход на реальном экране пока нужно подтвердить.

### Плитки для сенсорного экрана

Главная страница YaM содержит «Мою музыку», «Подобрано для вас», «Новые релизы», «Популярные плейлисты» и «Недавно слушали». Пустые разделы Яндекса не показываются. Кнопка Volumio переключает плитки и список; выбор вида сохраняется самим Volumio. Плейлисты используют обложки Яндекса (`cover.uri` или первое изображение `cover.itemsUri`); если обложки нет, остаётся штатная заглушка Volumio. Нажатие на плитку открывает список треков альбома или плейлиста, включая плейлисты других владельцев; страницы содержат до 50 треков. Нажатие на трек запускает его и открывает экран плеера. При сбое рекомендаций личная библиотека остаётся доступной. Отдельный каталог жанров и радиостанции пока не реализованы.

Разделы и формат обложек сверены с [исходным плагином achechulin](https://github.com/achechulin/volumio-plugins-sources/tree/master/yandex_music).
Запросы каталога используют `/landing3`, альбомы — `/albums/{id}/with-tracks`; форматы сверены с [клиентом Яндекс Музыки](https://github.com/MarshalX/yandex-music-api/tree/main/yandex_music/_client).
Реальная выдача персональных разделов зависит от аккаунта и ответа Яндекса; тесты используют фиксированные ответы API.

### Очередь и предыдущие треки (0.4.8)

Обычное нажатие на трек в YaM сохраняет существующую очередь и добавляет треки открытой страницы, начиная воспроизведение с выбранной песни. Кнопки страниц и недоступные строки в очередь не добавляются. Если та же страница уже стоит в конце очереди, штатный менеджер Volumio может использовать её повторно. Явное действие «Заменить и воспроизвести» сохраняет своё стандартное поведение.

После обновления обязательно перезагрузите страницу каждого браузера/сенсорного экрана: обработчик клика находится в клиентском расширении. Удалённые ранее записи автоматически не восстанавливаются. Кнопка «Предыдущий» использует стандартное поведение Volumio: первое нажатие во время воспроизведения возвращает к началу песни, повторное — к предыдущему треку.

### Переключение треков (0.4.9)

После выбора песни с плитки передаётся вся открытая страница треков, даже если кнопка Volumio передала только одну песню. «Следующий» использует порядок этой страницы в очереди. При запуске и продолжении источник управления остаётся YaM до первого обновления метаданных MPD; это исключает отправку команды «Следующий» в однотрековую очередь MPD в этот промежуток.

Перезагрузите страницу после установки. Простое открытие другого плейлиста не меняет воспроизведение: сначала выберите в нём песню. Режимы случайного воспроизведения и повтора остаются настройками Volumio; при повторе всей очереди её конец возвращает к началу, включая ранее добавленные треки. Автоматическая загрузка следующих страниц плейлиста пока не реализована.

Дополнительно в 0.4.9 введена защита от запоздалых обновлений MPD. Во время смены трека сообщения, начатые до или во время `stop/clear/add/play`, не передаются в состояние YaM. После команды запуска читается свежее состояние MPD. Это закрывает проверенный локальным тестом сценарий, когда старый `stop` ошибочно вызывает ещё один переход после запуска новой песни. При отключении плагина исходные обработчики MPD восстанавливаются; другие источники проходят без фильтрации.

**Статус проверки:** воспроизведение музыки подтверждено на устройстве; исправления 0.4.9 проверены локально и ещё требуют установки и повторения сценария «выбрать песню из „Премьеры“ → нажать „Следующий“ → дождаться следующего обновления». Сообщённое пользователем поведение «включается следующая, затем одна из прошлых» пока не считается подтверждённо устранённым. В состоянии устройства наблюдались `repeat: true`, `random: false`; сам по себе повтор не доказывает причину лишнего перехода. Поле `consume: true` также не доказывает удаление треков: Volumio выставляет его при приёме состояния MPD.

Ближайшие работы: проверка быстрых переключений и автоматического окончания трека, явное разделение истории и активного плейлиста, продолжение после 50-го трека, отдельный каталог жанров. Подробный порядок — в [PLAN.md](PLAN.md).
