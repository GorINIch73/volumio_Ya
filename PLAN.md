# План развития YaM — плагина Яндекс Музыки для Volumio

## Текущее состояние — 0.4.8

Плагин категории `music_service` работает через менеджер плагинов Volumio. Библиотека доступна в «Обзоре», воспроизведение и очередь — в общем плеере. Python-компонент обслуживает запросы аккаунта, библиотеки и MP3-ссылок через stdin/stdout.

Реализованы вход по токену, проверка аккаунта и выход, собственные плейлисты и «Мне нравится», страницы по 50 треков, добавление отдельного трека в очередь. Добавлены сохраняемый журнал ошибок и обновление из GitHub по кнопкам проверки и установки. Обновление использует менеджер Volumio, сохраняет предыдущий ZIP и перезапускает Volumio.

На устройстве подтверждены установка, вход и получение плейлиста. По журналу 0.4.3 обнаружено переполнение лимита из 16 запросов: загрузка метаданных блокировала запрос аудиоссылки. В 0.4.4 добавлены очередь с приоритетом аудиоссылки и кэш метаданных открытого плейлиста. Пользователь подтвердил воспроизведение на устройстве. В 0.4.7 добавлены обложки треков (600×600), с обложкой альбома при отсутствии обложки трека; нужно проверить отображение на устройстве. Отдельная ошибка «Некорректный адрес трека» пока не объяснена.

## 1. Проверить воспроизведение

- Установить текущий ZIP и получить диагностику запуска трека.
- Проверить разрешение MP3-ссылки, команды MPD и выбранный аудиовыход.
- Проверить паузу, продолжение, перемотку, переключение и автоматический переход между треками.
- Проверить недоступные треки, потерю сети, истечение токена и смену источника.

## 2. Проверить обновление и диагностику

- Проверить подготовку конкретной ревизии GitHub и установку штатным менеджером Volumio.
- Проверить сохранность аккаунта, предыдущего ZIP и журнала после обновления и перезапуска.
- Проверить повреждённый пакет, несовместимую версию, нехватку места, повторное нажатие и прерванное обновление.
- Проверить восстановление из предыдущего ZIP и понятность сообщения об ошибке.
- Добавить фильтрацию и скачивание диагностического отчёта без токенов и подписанных URL.

## 3. Расширить библиотеку и коллекцию

- Добавление целого плейлиста в очередь Volumio.
- Поиск треков, альбомов, исполнителей и плейлистов.
- Чтение, постановка и снятие лайка в Яндексе.
- Создание плейлиста, добавление и удаление треков с учётом владельца и ревизии.
- Подтверждение изменений по ответу API, обновление кэша и обработка конфликтов.
- Очередь Volumio и сохранённые плейлисты Яндекса должны оставаться разными сущностями.

## 4. Добавить «Мою волну»

- Проверить доступные методы API с реальным аккаунтом.
- Реализовать получение рекомендаций и пополнение очереди.
- Передавать события начала, завершения и пропуска трека с учётом пауз и перемотки.
- Проверить конец очереди, смену источника и восстановление сети.

## 5. Проверка на устройстве и выпуск

- Включение и отключение без дублирования источников и оставшихся Python-процессов.
- Сохранение аккаунта после перезапуска; выход без раскрытия токена.
- Совместная работа сенсорного интерфейса и телефона через Volumio.
- Звук через выбранный ЦАП, очередь и переходы между треками.
- Установка, обновление, восстановление и удаление через менеджер плагинов.
- Подготовка к публикации в магазине после проверки на целевом устройстве.

Локальные тесты используют фиктивные ответы API и не подтверждают работу реального аккаунта или аудиотракта. Операции изменения коллекции следует проверять отдельно на тестовом плейлисте.

В 0.4.7 добавлен переход на экран плеера в браузере, запустившем трек YaM. Установщик добавляет клиентский скрипт в HTML Volumio; проверить на телефоне и сенсорном экране после обновления страницы.

Для небольшого сенсорного экрана основная навигация — крупные плитки с обложками Яндекса, открывающие список треков по нажатию. В 0.4.7 реализованы рекомендации, новые релизы, популярные плейлисты и недавно прослушанные альбомы/плейлисты. Альбомы и плейлисты других владельцев открываются с пагинацией. Переключение плитки/список штатное. Отдельный каталог жанров остаётся следующим этапом.

В 0.4.8 обычный выбор трека YaM добавляет страницу к существующей очереди, вместо штатной замены очереди командой playItemsList. Проверить переход назад после выбора треков из разных страниц. Отдельно проверить возможное удаление при автоматическом окончании трека: consume=true в REST-состоянии сам по себе этого не доказывает.
